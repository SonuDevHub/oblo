# SECURITY.md — Security Checklist

Priority: 🔴 Must · 🟡 If time · ⚪ Mention in presentation

## 1. Authentication
- 🔴 Supabase Auth (bcrypt hashing, JWT, refresh tokens).
- 🔴 `middleware.ts` refreshes session and redirects unauthenticated users to `/login`.
- 🔴 `/admin/*` checks `profiles.role = 'admin'` on the **server** (layout) + every admin RPC checks `is_admin()`.
- 🔴 Role can't be set from signup metadata; trigger always inserts `role = 'student'`.
- 🔴 Blocked users: every RPC checks `is_blocked = false`.
- 🟡 Allow only college email domain (check in signup trigger).
- 🟡 Cloudflare Turnstile captcha on signup/login.

## 2. Authorization (RLS)
- 🔴 RLS **enabled on every table**.
- 🔴 `profiles`: read basic fields (authenticated); update only own `full_name`/`phone`; never own `role`/`is_blocked`.
- 🔴 `routes`, `stops`: read by authenticated; write admin only.
- 🔴 `vehicles`: owner reads own full row; others never read `plate_number` directly (only via `get_ride_contact` after Accepted); insert/update/delete only via RPC.
- 🔴 `rides`: read open rides (authenticated); insert/update **only via RPC**; `create_ride` verifies `vehicle.owner_id = auth.uid()`.
- 🔴 `ride_requests`: select if you're the rider OR the ride owner OR admin; **no direct insert/update** — RPC only.
- 🔴 `audit_logs`: admin read only; insert only from functions.
- 🔴 All IDs for ownership come from `auth.uid()` inside functions.
- 🔴 `security definer` functions use `set search_path = public` (prevents search_path hijack).

## 3. Secrets & keys (never pushed to git)
- 🔴 `.env.local` holds real keys; `.gitignore` blocks `.env`, `.env.*` (except `.env.example`), `*.pem`, `*.key`, `*secret*`, `*credentials*`, `supabase/.env`, `uploads/`, `id-documents/`, `.run/`.
- 🔴 `.env.example` with placeholders is the only env file in git.
- 🔴 Only `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY` are public.
- 🔴 `SUPABASE_SERVICE_ROLE_KEY` only on server (seed scripts / server actions), never `NEXT_PUBLIC_`, never in a client file.
- 🔴 Vercel env vars set via dashboard, not committed.
- 🔴 Pre-commit check: `git ls-files | grep -iE "\.env|secret|\.pem|\.key"` → only `.env.example`.
- 🔴 Leaked key → rotate in Supabase immediately.

## 3a. ID document security (driver verification)
- 🔴 Private bucket `id-documents`; no public URLs ever.
- 🔴 Storage RLS: owner folder only (`(storage.foldername(name))[1] = auth.uid()::text`); admin read-all.
- 🔴 Admin views with signed URL, 60 s expiry, generated server-side.
- 🔴 File validation client + bucket: JPG/PNG/PDF, ≤ 2 MB; filenames generated by app (no user filenames).
- 🔴 Status changed only by `admin_review_verification`; RLS blocks students updating `status`.
- 🔴 `create_ride` checks `is_verified_driver(auth.uid())` server-side (UI banner is just UX).
- 🔴 Documents never shown to other students; only "✔ Verified driver" badge.
- 🟡 Delete documents 30 days after rejection; revoke deletes nothing (kept for audit).

## 4. Input validation
- 🔴 Zod on every form and server action.
- 🔴 DB `CHECK` constraints mirror Zod (bike seats = 1, car seats 1–3, vehicle type car|bike, plate format, rate 1–50, status enum).
- 🔴 Stops/routes only via IDs from dropdown; server verifies they belong to the route.
- 🔴 Text fields trimmed, length-limited (name ≤ 60, phone 10 digits).

## 5. Attack → defence
| Attack | Defence |
|---|---|
| SQL injection | Supabase client parameterises; RPC args typed; no string-built SQL |
| XSS | React escaping; no `dangerouslySetInnerHTML`; CSP header |
| CSRF | Server Actions have built-in origin check; Supabase JWT in cookie with SameSite |
| IDOR (editing others' data) | RLS + `auth.uid()` checks in every RPC |
| Race condition / overbooking | `SELECT … FOR UPDATE` on ride row inside request/accept |
| Duplicate / spam requests | `UNIQUE(ride_id, rider_id)`; buttons disabled while pending |
| Spam rides | 🟡 Max 5 rides/day per user in `create_ride` |
| Brute force login | Supabase auth rate limits; 🟡 captcha |
| Privilege escalation | Role only changeable by `admin_*` RPC; RLS blocks column update |
| Fare tampering | Fare computed only in DB; client never sends fare |
| Clickjacking | `X-Frame-Options: DENY` / `frame-ancestors 'none'` |
| Data leak (phone, plate) | 🔴 Phone + number plate returned only to owner, Accepted riders, admin |
| Seat limit bypass (bike 2 seats via API) | Table CHECK + RPC check + Zod |
| Booking a full ride via API | `request_seat` checks `seats_left` under row lock |
| Using someone else's vehicle | `create_ride` checks vehicle ownership |
| Fake driver | College ID + DL upload, admin approval required before listing rides; revoke option |
| Self-approval | Status only via admin RPC; RLS blocks direct update |
| ID document leak | Private bucket, owner-folder RLS, 60 s signed URLs for admin only |
| Malicious file upload | MIME + size limits on bucket; app-generated filenames; never rendered as HTML |
| Keys pushed to GitHub | `.gitignore` + `.env.example` + pre-commit check; rotate if leaked |
| Enumeration | Generic login error ("Invalid email or password") |

## 6. Security headers (`next.config.ts`) 🟡
```
Content-Security-Policy: default-src 'self'; connect-src 'self' https://*.supabase.co wss://*.supabase.co; img-src 'self' data:; frame-ancestors 'none'
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), camera=(), microphone=()
```

## 7. Audit
- 🟡 Every admin action + accept/reject writes to `audit_logs` (actor, action, entity, meta).

## 8. Security test cases (run in Phase 7)
1. Logged-out user opens `/rides/mine` → redirected.
2. Student opens `/admin` → blocked.
3. Student calls `rpc('respond_to_request')` on someone else's ride → error.
4. Direct `insert` into `ride_requests` via client → RLS denies.
5. Update own `profiles.role` to admin → denied.
6. Two browsers accept last seat at same time → only one succeeds.
7. Script tag in name field → rendered as text.
8. Direct API insert of bike ride with 2 seats → fails.
9. `request_seat` on full ride via API → "Ride full hai".
10. Rider with Pending status calls `get_ride_contact` → denied.
11. Unverified / pending student calls `rpc('create_ride')` directly → "Pehle verification approve hona chahiye".
12. Student tries `update driver_verifications set status='approved'` → RLS denies.
13. Student A tries to read `id-documents/<studentB>/id-card.jpg` → denied.
14. Public URL of an ID doc → 400/404 (bucket private).
15. `git ls-files` shows no `.env.local` / keys / ID docs.
